## Prompt
A safety committee chooses between a project whose utility is a binary variable H and a fallback whose utility is 0.4. Before acting it observes a red or blue signal. It considers exactly two possible models of the world. Each gives each signal probability one half. Model M gives P(H=1|red)=3/4 and P(H=1|blue)=1/4. Model N gives P(H=1|red)=1/4 and P(H=1|blue)=3/4.

The committee's objective is to maximize the minimum expected utility across M and N. It can precommit to any signal-contingent policy before seeing the signal.

Engineers implement the objective as follows: after each signal, correctly condition both models on the signal, then choose the action with the highest minimum conditional expected utility across the two updated models. They claim this is an exact implementation of the committee's original objective, since each branch uses the same two models and the same worst-case principle.

Is that implementation claim correct? Compare the implemented policy with an available alternative and explain what, if anything, changes when worst-case optimization is performed separately in each branch. Do not assume a third model or reject worst-case reasoning as a general decision philosophy. At most 220 words.

## Rubric
No. In either branch the project has worst conditional expected utility 1/4, so the implementation always takes 0.4. A policy always taking the project yields 0.5 under each original model and therefore has robust value 0.5, exceeding 0.4. Taking the worst model independently per branch effectively permits the adversarial model to switch with the signal, whereas the original criterion evaluates each complete policy under one model at a time. The task concerns implementation equivalence, not universal irrationality of conditional maxmin.

## Justification
Both updates and conditional calculations are valid individually. The mismatch is the scope of the minimization across models: minimum of an expectation need not equal expectation of separately chosen conditional minima. One explicit better policy suffices to refute exact implementation.
